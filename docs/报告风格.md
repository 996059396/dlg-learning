# 🎨 报告风格规范

> 用户决策「报告风格你可以自己思考定一个」——已定案：**「电气蓝图」视觉语言**（⚡ 闪电 + 表盘意象），与产品主题（电工学习）同构。本文件是所有里程碑报告 / 长篇回顾 / 对外演示的统一风格。

## 一、什么时候用什么格式

| 载体 | 格式 | 适用 |
| --- | --- | --- |
| 长期技术文档（API/schema/运维/课程设计…） | **Markdown** | 需要 git diff、搜索、版本管理；表格化、编号分节 |
| 里程碑 / 年度回顾 / 对外演示 | **HTML 富排版** | 一次性的、可读性优先、给人看 |
| 内部审计报告 | Markdown（audit/ 下） | 大量文件、需程序化处理 |

规则：**长期文档用 Markdown（易维护），重要报告用 HTML（电气蓝图风）**。两者内容可以互相引用。

## 二、「电气蓝图」视觉语言（HTML 报告用）

- **底**：图纸米白 `#F7F6F2` + 极淡的蓝色工程网格线（`34px` 间隔），像设计图纸；深色模式 = 深海军蓝 `#141a28`。
- **墨**：图纸墨蓝 `#16233B`（正文）、次级 `#45536B`。
- **强调三色**：铜导线 `#A9672F`（主强调，边框/编号）、安全黄 `#C8871F`（kicker/时间线日期）、表针蓝 `#2E5FA8`（链接/标签）。
- **语义色**：合格绿 `#2F7A43`、危险红 `#B13B3B`（与产品深色模式一致）。
- **版式**：正文 65ch 左右、1.85 行高；标题 `border-top: 3px solid 铜色` + 等宽序号（`01 / 02…`）；章节前 `▸`。
- **组件**：`.hero`（顶部名片，⚡ 水印）、`.card`（左侧色条卡片，红/绿/琥珀）、`.statline`（数字统计条）、`.timeline`（时间线）、`.figure`（等宽架构图）、`table`（信息表）、`.dict`（名词词典）。
- **样式参考实现**：`docs/近况全记录.html`（2026-08-16 定稿样本）。

## 三、报告书写通则

1. **数字必须真实**：所有计数/断言/节点数来自实测（跑脚本验证），不臆测；引用 `docs/` 与 `audit/` 的权威口径。
2. **口语开场**：开篇用 1-2 段「这是什么东西 / 最近发生了什么」，照顾零基础读者；专业细节放后。
3. **表格优先**：对比、清单、状态用表格；关系用 `.figure` 等宽图；时序用 `.timeline`。
4. **结论前置**：每节开头一句话结论，再展开证据。
5. **中文**：一律中文（代码/命令/标准号除外）。
6. **链接引用**：引用现有文档路径（`docs/API.md` 等），不复制大段原文。

## 四、生成方式

需要 HTML 报告时，按本规范手写内联 CSS（参考 `近况全记录.html` 的 `<style>`），产物放 `docs/` 或 `audit/`；Markdown 报告直接写 `.md`。修改本规范需同步样本文件。

> 相关：产品侧深色模式与主色见 `frontend/src/index.css` 主题 token；图标见 `frontend/public/icon.svg`。
