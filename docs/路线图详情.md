## 二、路线图推进纪律

### 2.1 任务推进顺序（roadmap 八步，`CLAUDE.md` 固化）

```
鉴权基线 → 测试隔离 → 判分真源 → 结算事务 → 奖励闭环 → 错题SM-2 → 内容硬错误 → 内容CI
```

每一步都有「先立不可推翻的基线」的含义：判分先真源化、再谈奖励；内容先过硬错误、再接 CI。后续所有里程碑（A–G、模拟考、多轮审计修复）都是在这条主链上的延展。

### 2.2 发布门禁

```bash
cd backend && npm test        # 10 段链，182 断言 + 判分/数据完整性扫描（2026-08-17 实测）
cd frontend && npm run build  # 前端构建成功
```

- 内容改动必须过 `validate_content.cjs`（0 ERROR）+ `grade_scan.cjs`（全量 100%）+ `check_data_integrity.cjs`（零孤儿）。
- CI（公开仓 `github.com/996059396/dlg-learning`）：`gate` / `frontend-test` / `desktop-smoke` / `e2e-browser` 四个 job × 三 OS（ubuntu/macos/windows）× Node 24。
- **Node ≥ 24 是硬性**：better-sqlite3 v13 只预编译 Node ABI 137，Node 20 会段错误（本文档所有实测均用 Node 24.19.0）。

### 2.3 口径同步义务

门禁数字（断言数/节点数/课时数）变更时，需同步 `CLAUDE.md`、`README.md`、`docs/快速开始.md`、`docs/测试说明.md` 四处。**本轮实测发现该义务近期再次失效**（详见 §七）。

### 5.2 已接受取舍（显式记录）

- **课程接口答案键**：GET lesson 返回答案键供前端即时本地反馈 → 登录用户可读到答案、答满分拿合法奖励/排名。这不铸币（奖励服务端独立判分），残留是「排行榜满分机器人」；`lesson-views` 限流已挡整库抓取。见 `CLAUDE.md`「已知取舍」。
- **快照 vs 实时重判**（crosscheck5 M4）：错题卡复习按实时节点重判、揭示的却是快照答案，两者在节点答案被编辑后可能分歧——当前以「复习判分以服务端实时重判为准」为准。
- **双队列注释失真**（crosscheck5 M5）：`QUEUE_REVIEW_CAP=50/QUEUE_NEW_CAP=20` 因路由 limit≤30 永不生效。**2026-08-17 已修**：移除 QUEUE_REVIEW_CAP，改为语义真正生效的 `DAILY_REVIEW_CAP=30`（每日只服务最紧迫 30 张到期复习，其余惰性顺延——逾期越久 R 越低自然升到最前）+ `DAILY_NEW_CAP=20` 每日新增摄入预算（满 20 张顺延次日），配套 leech 优先排序与 mastered 90 天复检（见 test_sm2.mjs 43 断言）。
