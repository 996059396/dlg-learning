# 🏛️ 架构说明

## 一、总览

前后端分离的单体应用，一个 Node 进程同时承载 API 与静态站点：

```
┌────────────────────┐       /api 代理(开发)        ┌──────────────────────┐
│   React 18 + Vite  │ ──────────────────────────► │  Express + better-sqlite3 │
│   frontend/dist    │ ◄────────────────────────── │  backend/server.js    │
└────────────────────┘    JSON / 静态资源          │        │             │
                                                   │   routes/  lib/       │
                                                   │        ▼             │
                                                   │  data/app.db (SQLite) │
                                                   └──────────────────────┘
```

- **开发模式**：前端 Vite dev server（5173）把 `/api` 代理到后端 3001。
- **生产模式**：`npm run build` 后，后端直接静态托管 `frontend/dist`，只跑一个进程。
- 课程内容是 JSON 文件（`backend/data/courses/`），**按请求实时读盘**——改内容刷新即生效，无需重启、无需编译。

## 二、请求 → 判分 → 落库 链路（核心路径）

以「完成一个微课练习」为例：

```
前端 LessonPlayer ──► POST /api/courses/:cid/units/:uid/lessons/:lid/complete
                          │  requireAuth（sessions 表鉴权）
                          ▼
                     逐节点判分（backend/lib/grading.js）
                         │  gradeNode(node, userAnswer)
                         │  _normalize：去所有空白 + 全角转半角
                         ▼
                     事务内写库：
                        progress  ← 课程进度（completed_at）
                        mistakes ← 错题（供 SM-2 复习）
                        node_results ← 逐节点结果（统计 p-value）
                        game_state ← 金币 / 经验 / 生命
                          │
                          ▼
                     返回 { score, mistakes, earned… }
```

**判分原则：服务端为准。** 前端只提交 `nodeId + 用户答案`，所有正确性判定、奖励发放都在服务端完成，前端不可伪造成绩。

## 三、数据模型（SQLite）

建表见 `backend/models/database.js`，核心表：

| 表 | 用途 |
| --- | --- |
| `users` | 账号，`password_hash` 为 scrypt 哈希（绝不存明文） |
| `sessions` | 会话 token（不透明随机串，哈希存储） |
| `game_state` | 金币 / 经验 / 生命 / 连击 / 签到 |
| `progress` | 课程-单元-课完成记录 |
| `mistakes` | 错题本（SM-2 调度字段：interval/repetitions/ease） |
| `review_credit` | 复习奖励额度 |
| `inventory` / `inventory_new` | 道具商店库存 |
| `leaderboard` / `leaderboard_new` | 段位排行榜快照 |
| `league_history` | 周结算历史 |
| `node_results` | 逐节点作答统计（题目难度 p-value 的数据源） |
| `exam_sessions` | 模拟考会话 / 成绩 / 答案 |

> 数据库文件 `backend/models/data/app.db` 含真实用户数据（含密码哈希），**已被 .gitignore 排除**，切勿提交。克隆仓库后首次启动会自动建库。

## 四、鉴权体系

- **用户鉴权**：`POST /api/auth/register` / `/login` 签发会话 token，前端存 localStorage，请求带 `Authorization: Bearer <token>`。
- **管理鉴权**：`ADMIN_TOKEN` 环境变量 + `x-admin-token` 请求头（如周结算、后台接口）。未配置时这些接口 fail-closed 返回 503。
- 路由中间件见 `backend/middleware/auth.js`。

## 五、题库内容管线

内容 JSON 由 `parser/`（讲义转结构化）与 `scripts/`（校验 / 修复）工具链维护：

```
石群讲义等素材 ──► parser/（分块、结构化）──► backend/data/courses/<course>/<unit>.json
                                                  │
                                              scripts/validate_content.cjs（门禁）
                                                  │
                                           前端实时读盘渲染
```

每次内容改动都必须通过 `validate_content.cjs`（0 ERROR）才算合格，防止把结构错误带入线上。

## 六、可扩展点

- **加课程**：在 `backend/data/courses/<新id>/` 下放单元 JSON，并在 `index.json` 注册。
- **加题型**：`backend/lib/grading.js` 加一个 `case`，前端 `LessonPlayer.jsx` 加对应渲染器。
- **改游戏规则**：金币/生命/段位参数集中在 `backend/routes/game.js` 的路由常量与 `backend/lib/shop.js`。
- **判分审计**：`node_results` 表可按 nodeId 汇总正确率，支撑题库校准。
