# 🌐 部署指南

单进程、单文件数据库，部署非常简单。三种方式任选。

## 方式一：本地 / 内网自用（最简单）

> **Node ≥ 24**（better-sqlite3 预编译二进制在 Node 20 段错误）。Windows 本机可用 nvm-windows 或解压 Node 24 zip 到任意目录，用该 node.exe。

```bash
cd backend
npm install --production
node server.js
```

启动后后端同时托管 `frontend/dist`，浏览器访问 **http://localhost:3001** 即可。适合自己一台机器用。

> 前提：`frontend/dist` 已构建（`cd frontend && npm run build`）。

## 方式二：Linux 服务器（云主机 / NAS）

```bash
# 1. 准备
git clone <你的仓库> dlg && cd dlg
curl -fsSL https://deb.nodesource.com/setup_24.x | bash - && apt install -y nodejs

# 2. 依赖（前端构建需要完整依赖）
cd backend && npm install
cd ../frontend && npm install && npm run build

# 3. 环境变量（可选，管理功能需要）
export ADMIN_TOKEN="你的管理口令"

# 4. 后台运行（systemd 或 pm2）
cd ../backend
npm install --production
nohup node server.js > server.log 2>&1 &
# 或用 systemd 服务单元托管，开机自启
```

## 方式三：Docker（可选）

项目没有内置 Dockerfile，但可以最小化自建：

```dockerfile
FROM node:24-slim
WORKDIR /app
COPY backend backend
COPY frontend/dist frontend/dist
WORKDIR /app/backend
RUN npm install --production
EXPOSE 3001
CMD ["node", "server.js"]
```

```bash
docker build -t dlg .
docker run -d -p 3001:3001 -e ADMIN_TOKEN=你的口令 -v dlg_data:/app/backend/models/data dlg
```

**注意**：`-v` 挂载数据卷很重要——SQLite 数据库在容器重建后要持久化。

## 面向公网（重要提醒）

- **必须用 HTTPS**（HTTP 明文会泄露会话 token）。云主机用 Nginx/Caddy 反代 + Let's Encrypt 证书，或直接用云厂商负载均衡器。
- **ADMIN_TOKEN 必须设置一个强随机值**，否则管理接口拒绝服务（503），这是默认 fail-closed 行为。
- **别把 `app.db` 传上去**：它含真实用户密码哈希。本仓库 `.gitignore` 已排除，部署时用干净数据库启动。
- 备案：如果使用大陆云主机 + 域名对外服务，按所在云厂商要求完成 ICP 备案。
- 并发量级：better-sqlite3 单文件，适合小规模（几十~几百并发以内）。更大规模建议换 PostgreSQL + 横向扩展（非本项目当前目标）。

## 端口与代理

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 后端端口 | `3001`（`PORT` 环境变量可改） | 监听 `0.0.0.0` |
| 前端开发 | `5173`（Vite） | 仅开发用，`/api` 代理到 3001 |
| 反向代理 | Nginx 80/443 → 3001 | 生产推荐，配 HTTPS |

## ADMIN_TOKEN 管理口令

管理接口（周结算 `POST /api/game/league/_admin/settle`、内容管理）由 `ADMIN_TOKEN` 环境变量守卫，**没有默认值**——未设置时管理接口一律拒绝服务（503 fail-closed），这是有意为之，防止旧的公开默认口令被撞库利用。

**生成强随机值：**

```bash
openssl rand -hex 32
```

**设置与调用：**

```bash
export ADMIN_TOKEN="$(openssl rand -hex 32)"   # 后端启动前
curl -X POST http://localhost:3001/api/game/league/_admin/settle \
  -H 'Content-Type: application/json' \
  -H 'x-admin-token: '"$ADMIN_TOKEN" \
  --data '{"force":false}'
```

要点：

- 请求通过 **`x-admin-token` 请求头**携带，与用户会话 token（`Authorization: Bearer ...`）互不相干；口令在服务端用恒时比较。
- 兜底路径：`ADMIN_USER_ID` 环境变量指向的用户 id 也可直接以登录态调管理接口（预留，目前未使用）。
- **别把 `ADMIN_TOKEN` 写进前端**（浏览器能看到的东西就不叫口令），也别提交进 git；只在服务端环境里设置。
- Docker 方式见上面 `docker run -e ADMIN_TOKEN=...`；systemd 用 `Environment=ADMIN_TOKEN=...`。
- 管理结算本身限流（每 IP 30 次/15 分钟），防止弱口令在线撞库重写全服排行。

## 升级

```bash
git pull
cd frontend && npm run build   # 前端有变更时
cd ../backend && npm test       # 先跑门禁
# 重启后端进程
```

内容更新无需重启（实时读盘），仅代码变更需要重启后端。
