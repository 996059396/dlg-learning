# 🛠️ 运维手册

面向**生产/长期运行**场景的操作手册：单实例守护、备份与回滚、日志、健康检查、升级、故障排查。开发环境起步见《快速开始》，部署见《部署指南》。

---

## 一、运行形态

单进程 Node 应用，一个进程同时提供 API 与静态站点（`frontend/dist`）。**必须用 Node 24**：

- better-sqlite3 v13 预编译二进制对应 Node ABI **137**；Node 20（ABI 115）下 `require` 直接段错误，且无清晰报错。
- `server.js` 启动时有 ABI 预检：不匹配立即打印 `[fatal] Node ABI = ...` 并 `exit 1`。
- 本机二进制：`C:\Users\moxo\node24\node.exe`（与其他项目共用 Node 20 互不影响）。

**单实例约束**：SQLite WAL 允许多进程读，但**两个实例并发写 `app.db` 会损坏 WAL**。因此：

1. `server.js` 启动时**端口互斥探测**（`portInUse`）：端口已被占 → 打印 `[fatal] 端口 ... 已被占用` 并 `exit 1`，绝不第二个打开 `app.db`。
2. 守护脚本用 **pidfile + `kill -0`** 双重防重：重复启动（开机自启与手动启动重叠）直接 `exit 0`。

> 结论：**一台机器只跑一个实例**。不要在同一台机器上起第二个 server（换端口也不行——第二个实例会开同一个 app.db 文件）。

### 守护脚本（本机 live）

`/d/tmp/dlg_server_guard.sh`（内含生产 `ADMIN_TOKEN`，**属机密，勿外泄/勿提交仓库**）：

- 显式用 `node24` 二进制启动 `server.js`。
- 日志追加到 `/d/tmp/dlg_server.log`。
- `while true` 循环：进程退出 2 秒后自动重启（配合 `server.js` 的 fail-fast：`uncaughtException` / `listen` 失败 / 端口被占都会 `exit 1`，由 guard 兜底拉起）。
- 开机自启 + 手动启动重叠时靠 pidfile 去重。

## 二、环境变量全表

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `ADMIN_TOKEN` | 管理功能 | 无（缺省管理接口 **503**） | 管理接口 `x-admin-token` 请求头鉴权；服务端恒时比较 |
| `ADMIN_USER_ID` | 否 | 无 | 该用户 id 可直接以登录态调管理接口（预留） |
| `PORT` | 否 | `3001` | 后端端口 |
| `HOST` | 否 | `0.0.0.0` | 监听地址；`127.0.0.1` 只限本机 |
| `CORS_ORIGINS` | 否 | `localhost:5173/4173` | 逗号分隔允许跨域来源（生产同源一般无需设） |
| `DLG_DB_PATH` | 否 | `backend/models/data/app.db` | 数据库路径（测试隔离库用） |
| `DLG_BACKUP_DIR` | 否 | `backend/models/data/backups/` | 备份输出目录（`*.db` 已被 gitignore） |
| `DLG_RATE_MAX_<scope>` | 否 | 生产限流值 | **仅测试**放宽限流；生产绝不设置 |

PowerShell 设置示例：

```powershell
$env:ADMIN_TOKEN = "改成你的管理口令"
node server.js
```

## 三、定时任务（内置 cron，Asia/Shanghai）

| 任务 | 时机 | 说明 |
| --- | --- | --- |
| 周结算 `settleWeek` | 每周一 **00:00** | 升降段 + 写 `league_history`；幂等 |
| 启动补账 `catchUpSettlements` | 每次启动 | 离线期间错过的周一边界补结算（旧→新） |
| 每日备份 `backupDatabase` | 每日 **03:47** | `db.backup()` WAL 安全快照 → `DLG_BACKUP_DIR/app-YYYYMMDD.db`；**当日已有同名文件则跳过**（幂等） |

- 服务器**周一会停机维护**的，重启后会自动补上周结算，无需人工。
- 手动触发结算：`POST /api/game/league/_admin/settle`（`x-admin-token` + `{"force":false}`）。

## 四、备份与回滚

### 4.1 备份的三道线

1. **每日自动**：03:47 cron → `backups/app-YYYYMMDD.db`。
2. **升级/内容改动前手动快照**（推荐，加备注）：

   ```bash
   cd /d/dlg_project
   /c/Users/moxo/node24/node.exe scripts/backup_db.cjs before_s13_content_update
   # → backups/app-YYYYMMDDHHMMSS_before_s13_content_update.db
   ```

3. **发布前整目录快照**（含前端 dist 与内容 JSON）：直接复制 `backend/models/data/` 到带时间戳目录即可（内容 JSON 在 `backend/data/courses/`，随 git 走）。

> 备份是 `better-sqlite3 db.backup()`，**WAL 下纯 `fs.copyFile` 会丢未 checkpoint 的数据**，不要用 cp 代替。

### 4.2 回滚

```bash
# 1. 停服：guard 是 `while true; do node server.js; done`，只 kill guard 父进程会留下
#    node 子进程孤儿化（仍持有 3001 端口与打开的 app.db）。必须连服务进程一起终止：
#    Windows 用 taskkill /T 杀进程树；Linux 用 `kill -- -<pgid>` 或 pkill -f server.js
#    （先停 guard，避免它 2 秒后又把 node 拉起来）
kill <guard_pid>                      # 停守护循环
taskkill /T /F /PID <node_server_pid>  # 终止 node server（Windows；先查 netstat -ano 找 3001 PID）

# 2. 清掉残留 WAL（服务被强杀时未 checkpoint 的 -wal/-shm 会在下次打开时重放，
#    覆盖进去的旧库会被污染的 WAL 污染）
rm -f backend/models/data/app.db-wal backend/models/data/app.db-shm

# 3. 还原数据库（先备份现场，再覆盖）
cp "backups/app-<日期>_<备注>.db" backend/models/data/app.db

# 4. 如需回滚代码：git checkout <旧版本>（只回滚代码不影响 db）
# 5. 重启 guard
bash /d/tmp/dlg_server_guard.sh
```

**破坏性操作铁律**：清表 / 删用户 / 手动改库 / 迁移前，**必须先跑 `backup_db.cjs` 快照**，否则视为事故。数据库含真实密码哈希，任何回滚副本都不得进 git / 不得上传。

## 五、日志

- **运行日志**：guard 追加到 `/d/tmp/dlg_server.log`。默认不轮转，长期运行请配外部轮转（见下）。
- **关键日志行**：
  - `[fatal] ...` — 启动失败/崩溃（`exit 1` 由 guard 重启）
  - `[cron] Weekly settlement triggered` / `[settleWeek] ...` — 周结算
  - `[backup] 每日备份完成 → ...` — 每日备份
  - `[boot] Caught up N missed settlement entries` — 启动补账
  - `[error] ...` — 请求级错误（含 SQL 内部细节，仅日志，不返给客户端）
- **轮转建议**（Windows：可用任务计划程序按天归档；Linux：`logrotate`）：

  ```
  /d/tmp/dlg_server.log {
    daily
    rotate 30
    compress
    copytruncate
  }
  ```

  注意 `copytruncate`：guard 用 `>>` 追加，日志文件被 rename 后新文件会重新创建，无需重启进程。

## 六、健康检查与探活

`GET /api/health`（无鉴权）：

```json
{ "status": "ok", "timestamp": "2026-08-15T..." }
```

- 探活建议每 30–60 秒打一次；连续 N 次失败 → 告警并检查 guard。
- 验证业务可用性可再加一层：`GET /api/courses` 返回 200 且含 `electrician_basics`。

## 七、数据完整性巡检

内容改动 / 升级后跑数据完整性哨兵（只读，不改库）：

```bash
cd /d/dlg_project/backend
/c/Users/moxo/node24/node.exe ../scripts/check_data_integrity.cjs
# ✅ Data integrity OK (704 lessons, no orphans, no NULL node_id)
```

- 检查：错题卡 `lesson_id`/`node_id` 是否仍存在、progress 指向的课是否存在、`users` 表非空、外键零违规。
- **内容编辑若删/改写了课**（recut/重构）导致孤儿，必须跑 `scripts/cleanup_data_hygiene.cjs` 清理，否则错题本会永远卡在无法 master 的卡片上。

## 九、公网部署注意

- **必须 HTTPS**：明文 HTTP 会泄露会话 token（Bearer）。
- 反向代理（Nginx/Caddy）或隧道（cloudflared/cpolar）均可。`server.js` 已 `trust proxy: 'loopback'`——仅信任回环来源的 `X-Forwarded-For`，所以：
  - 隧道（本机 cloudflared → 127.0.0.1）能取到真实客户端 IP 用于限流；
  - 外部客户端**无法**伪造 XFF 绕过限流。
- 若用隧道，`HOST` 保持 `127.0.0.1` 更安全（只让隧道/本机访问），API 限流仍按真实 IP。
- 大陆云主机 + 域名对外服务按云厂商要求完成 **ICP 备案**。
- 量级：better-sqlite3 单文件适合几十~几百并发；更大规模非当前目标。

## 十、故障排查速查

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 启动即 `[fatal] Node ABI = ...` | 用错了 Node 版本 | 用 `C:\Users\moxo\node24\node.exe` |
| 启动即 `[fatal] 端口 ... 已被占用` | 已有实例在跑（或别的进程占 3001） | 不要起第二个；查占端进程；确认 guard 单实例锁 |
| 管理接口 503 | 未配 `ADMIN_TOKEN` | guard 里已固化；若手动启动需 `$env:ADMIN_TOKEN=...` |
| 管理接口 403 | `x-admin-token` 不对 | 核对环境变量值 |
| 页面白屏/资源 404 | 旧 `index.html` 指向已删除的 hash 资源 | 重新 `npm run build` 并清浏览器缓存；`index.html` 永不缓存（D2 修复） |
| `/api/health` 超时 | 进程崩了 | 看 `/d/tmp/dlg_server.log` 尾部 `[fatal]`；guard 应已重启 |
| 周结算没发生 | 周一 00:00 服务器停机 | 启动时自动补账；或手动 `_admin/settle` |
| 改了课程 JSON 没生效 | — | 内容实时读盘，刷新页面即可；索引变了也会热加载 |
| 备份文件不存在 | 当日已备份（幂等跳过） | 看日志 `[backup] 每日备份完成` 或手动 `backup_db.cjs` |

## 十一、机密与红线（务必遵守）

- `ADMIN_TOKEN`（guard 脚本内）与任何 `app.db` 备份/副本：**不得外泄、不得进 git、不得上传**。
- 备份目录 `backend/models/data/backups/`、`app.db*` 均在 `.gitignore`。
- 删除/覆盖数据库前必须先快照；任何「回滚到旧库」操作先备份现场。
- 生产库与内容数据严格分开：内容 JSON 进 git（公开仓可发布），`app.db` 永不进仓。
