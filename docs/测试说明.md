# 🧪 测试说明

本项目的测试是**自写 test()/ok() 计数助手 + Node 原生脚本**（不用 node:test，不用任何测试框架），`npm test` 一键跑全量门禁。前端另有 vitest 单测（纯逻辑模块）。

> **Node ≥ 24（硬性）**：better-sqlite3 v13 只预编译 Node ABI 137，Node 20 下 `require` 直接段错误且无清晰报错。本机用 Node 24 二进制（如 `node24` 目录下的 node.exe，或 nvm 切到 24；命令示例中 `node24` 指该路径）。`test_api.mjs` / `test_security_invariants.mjs` / `scripts/backup_db.cjs` 首行有 Node 版本守卫，其余脚本无（误用 Node 20 会段错误）。

## 一、一键全量门禁

```bash
cd backend
npm test
```

`npm test` 是一条 `&&` 串联的脚本链（见 `backend/package.json`），任一环节失败即整体失败（fail-fast，后续段不跑）：

| 环节 | 脚本 | 断言数 | 作用 |
| --- | --- | --- | --- |
| 内容校验 | `node ../scripts/validate_content.cjs` | 5029 节点 0 ERROR | 扫描全部课程 JSON 结构/判分键/id 唯一性（**只 ERROR 阻断，WARN 不阻断**） |
| 接口测试 | `node ../test_api.mjs` | 47 | 注册/登录/课程/进度/判分/金币/红心门禁/幂等 |
| 里程碑测试 | `node ../smoke_milestone1.mjs` | 20 | 核心业务流程冒烟（练习→判分→奖励闭环） |
| 排行榜测试 | `node ../test_leaderboard_v2.mjs` | 12 | 段位/周结算/排行/幽灵榜 |
| 结算测试 | `node ../smoke_settlement.mjs` | 14 | 周结算补账、当前周不被动、幂等 |
| 安全不变量 | `node ../test_security_invariants.mjs` | 19 | 错题卡脱敏、register 独立桶、login-user-global 兜底、模拟考及格路径、多选 remap、5 类答案键剥离、rate_limit 桶、simulation_danger 负例 |

## 二、内容校验器（最重要的一道门）

```bash
cd backend
node ../scripts/validate_content.cjs
```

- 扫描 `backend/data/courses/**` 与 `data/exam/` 下所有 JSON。
- 检查：id 全局唯一、node 结构完整、判分节点答案键可被 `gradeNode` 判定、simulation_dial 角度分离度等。
- 输出 `0 ERROR / 0 WARN / N 节点` 才合格——**只有 ERROR 使脚本 exit 1，WARN 仅是提示**。
- **任何内容改动都必须过这道门**，防止把结构错误带进线上。

> 数据完整性（孤儿引用/外键/重复卡）由 `scripts/check_data_integrity.cjs` 单独检查（`npm run test:data`）；判分自洽由 `grade_scan.cjs` 检查（`npm run test:grade`）。三者职责不同，别混淆。

## 三、前端测试（vitest）

```bash
cd frontend
npm test   # vitest run（api/offlineQueue/sessionCache/GameContext 4 个模块，24 用例）
npm run build
```

- vitest 环境为 node（无 jsdom），只测**纯逻辑模块**（localStorage/fetch 由 test/setup.js 提供最小 polyfill）。
- 组件/页面（LessonPlayer、MockExam、GameContext 等）目前**无自动化测试**——改动前端组件请至少 `npm run build` 过 + 手测，CI 有 `frontend-test` job（三 OS）跑 vitest + build。

## 四、测试数据隔离

- 接口/里程碑/排行/结算/安全/幂等套件均**自建独立 SQLite 临时库**（`DLG_DB_PATH` 指向 `os.tmpdir()` 下临时文件）+ 独立端口（3995–3999），**不碰真实 `app.db`**，可反复运行。
- **唯一例外**：`check_data_integrity.cjs` 以**只读**方式打开真实 `app.db`（`readonly: true`）做完整性巡检；app.db 不存在时打印 skip 并 exit 0。
- 各套件端口固定（3995/3996/3997/3998/3999），**不要并发跑两路 npm test**（端口会撞车，报错难辨）；上一轮进程未清干净时先 `netstat -ano | grep 399x` 清理。
