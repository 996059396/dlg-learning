# 📦 课程内容结构指南

课程内容全部是 **JSON 文件**，不依赖数据库。这是本项目最重要的可扩展面。

## 一、存放位置

```
backend/data/
├── courses/
│   ├── index.json              # 课程目录索引（前端课程树用）
│   ├── electrician_prereq/     # 电工零基础前置（4 单元）
│   │   └── e1_intro.json       #   一个单元一个 JSON
│   ├── electrician_basics/     # 初级电工理论（11 单元）
│   └── electrician_exam/       # 电工考证主线（13 单元）
└── exam/
    └── multi_select.json       # 多选题池（模拟考用）
```

> ✅ **单元文件结构唯一**：`backend/data/courses/<course>/<unit>.json` 一律是**顶层直接含 `lessons` 数组的单个对象**：
> ```jsonc
> { "id": "u1_intro", "title": "初识电工", "lessons": [ ... ] }
> ```
> 数组形式（`[ {...} ]`）或 `{ units: [...] }` 包装会被 `scripts/validate_content.cjs` **直接拒绝**（审计 B1/B2 修复：运行时 `loadLesson` 只消费顶层 `lessons`，校验器门禁结构 = 运行时结构）。课程元信息放在 `index.json`（各课程根目录一份）。

## 二、层级结构

```
课程 course ──► 单元 unit ──► 课 lesson ──► 节点 node
```

```jsonc
// backend/data/courses/<course>/<unit>.json
{
  "id": "u1_intro",
  "title": "初识电工",
  "lessons": [
    {
      "id": "l1_what_is_electricity",
      "title": "什么是电",
      "nodes": [
        {
          "id": "l1_what_is_electricity_n1",   // 全局唯一
          "type": "info",                        // 教学卡（不判分）
          "content": "电流的本质是电荷的定向移动……"
        },
        {
          "id": "l1_what_is_electricity_n2",
          "type": "multiple_choice",             // 判分题型
          "question": "下列哪个是电流的单位？",
          "options": [
            { "id": "A", "text": "伏特（V）", "is_correct": false },
            { "id": "B", "text": "安培（A）", "is_correct": true },
            { "id": "C", "text": "欧姆（Ω）", "is_correct": false },
            { "id": "D", "text": "瓦特（W）", "is_correct": false }
          ],
          "explanation": "电流单位是安培（A）。伏特是电压，欧姆是电阻，瓦特是功率。"
        }
      ]
    }
  ]
}
```

## 三、节点类型（type 字段）

| type | 是否判分 | 关键字段 | 数量 |
| --- | --- | --- | --- |
| `info` | 否 | `title` + `content` 教学卡正文 | 1,278 |
| `multiple_choice` | ✅ | `question` + `options[{id,text,is_correct}]`（正确项 `is_correct: true`） | 1,550 |
| `true_false` | ✅ | `question` + `correct_answer`（`true`/`false`） | 1,091 |
| `fill_blank` | ✅ | `question`（含 `__` 空位）+ `answer` + `acceptable_answers[]`（可接受答案） | 919 |
| `match` | ✅ | `question` + `pairs[{left,right}]`（判分比对「左 = 右」序列） | 70 |
| `sort` | ✅ | `question` + `items[{id,text}]` + `correct_order[]`（item id 顺序） | 45 |
| `multimeter_challenge` | ✅ | 万用表实操模拟：`correct_setup{dial,red_port,black_port,…}` + `target{hotspots}` + `dial_options[]` | 18 |
| `simulation_danger` | ✅ | 安全操作序列；答对前端提交 `'安全操作'`（判分正则 `/安全操作/`） | 3 |
| `simulation_dial` | ✅ | `question` + `dial_options[{label,is_correct}]` | 3 |
| `simulation_probe` | ✅ | `correct_probes{red,black}` + `hotspots{}`（+ 可选 `allow_swap`） | 2 |
| `drag_drop` | ✅ | 拖拽到目标区，判分比对 `target_zone.label` | 2 |
| `multi_select` | ✅ | `question` + `options[{id,text,is_correct}]`（正确项 ≥2，集合相等判分）——**仅存在于模拟考多选题池**（`data/exam/multi_select.json`） | 10（池内） |

判分核心在 `backend/lib/grading.js` 的 `gradeNode(node, userAnswer)`，字段名以 `extractAnswer`/`gradeNode` 为准。

## 四、判分规则要点（易踩坑）

1. **空白不敏感**：判分前会去掉所有空白字符、全角转半角。所以 `"安培（A）"` 与 `"安培(A)"` 等价。
2. **多选题判无序**：`is_correct: true` 的选项 id 集合相等即算对，提交顺序任意。（`multi_select` 池每题至少 2 个正确项。）
3. **解释字段**：判分节点的 `explanation` 是学生答错后看到的解析，务必写清「为什么」，不要只复述答案。
4. **MC 选项排序**：`options` 建议按 `id` 字母序排列（A/B/C/D），前端按数组顺序显示字母。

## 五、新增一门课 / 一个单元的步骤

1. 新建 `backend/data/courses/<course_id>/<unit_id>.json`（结构见上）。
2. 若没有该课程目录，创建目录并给它建 `index.json`（课程元信息）。
3. 更新 `backend/data/courses/index.json` 的 `units` 列表与 `lesson_count`。
4. 跑校验：
   ```bash
   cd backend
   node ../scripts/validate_content.cjs   # 期望 0 ERROR
   ```
5. 跑全量门禁：
   ```bash
   npm test   # 期望 109 断言全绿
   ```
6. 重启后端（内容虽是实时读盘，但 index 变更建议重启确认）。

## 六、内容质量红线

- `id` 必须全局唯一（校验器会查）。
- 判分节点必须能被 `gradeNode` 判分（各题型判分字段见上表），且判分路径在 `scripts/validate_content.cjs` 覆盖内。
- `info` 教学卡不要带「判定语」（如「回答正确」），那是判分节点解释的专属。
- 题干与选项引用具体数字/标准时以国标（GB/T）为准，标注适用范围（如美国 NEC 语境要注明）。
