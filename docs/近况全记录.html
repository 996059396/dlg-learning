01这是什么东西

一个「电工考证」备考平台

这个项目代号 DLG（全称「DLG 电工学习系统」），本质是一个在线学习 App：你注册一个账号，选课程、学微课、做题，系统帮你判分、攒金币、练错题，最后还能来一场模拟考试，模拟低压电工上岗证的笔试。它是给准备考「低压电工作业操作证」这类证书的人用的。

打个比方：它有点像「多邻国（Duolingo）学英语」之于语言，但内容是电工知识——万用表怎么用、欧姆定律、接触器、星三角降压启动、接地防雷、触电急救……全套电工考证要考的东西。

它由什么组成

部分技术通俗说法
前端React 18 + Vite 7你在浏览器里看到的页面（课程列表、做题界面、排行榜）
后端Express + SQLite藏在后台的服务器：处理登录、判分、发金币、存错题
内容JSON 文件705 节课、5029 道题，全部写成纯文本文件，改一下刷新就生效
数据库SQLite 单文件一个文件装下所有用户、进度、错题、排行榜

它现在长什么样

打开就是注册/登录页；登录后首页有「学习连胜」（签到天数）；课程页分成三块：零基础前置课、初级电工理论、考证主线；学完一节会判分、发经验值和金币；错题会进「错题医疗包」，按记忆曲线提醒你复习；每周一凌晨按经验值结算段位，青铜→白银→黄金→翡翠→钻石。

02零基础概念课

接下来这份回顾里会反复出现几个词，先花三分钟把它们讲明白。已经懂的人可以直接跳到第三章。

什么是「前端」和「后端」

一个网站分两半。你在浏览器里看到、点击、输入的，叫前端（frontend）；在远方的电脑（服务器）上运行、存数据、算成绩的，叫后端（backend）。前端负责「好看」，后端负责「可靠」。本项目里前端用 React 写，后端用 Node.js + Express 写。

什么是「数据库」

数据库是「存数据的仓库」。本项目用的是 SQLite，一个单文件数据库——整个数据库就是一个文件（app.db），里面用很多张表存数据：用户表、进度表、错题表、排行榜表……表之间有关联（谁是谁的错题）。单文件的好处是：部署简单、搬走就是一个文件。

为什么判分必须在「服务端」

这是本项目的核心安全设计，值得多讲两句。

判分在服务端 = 客户端不能作弊

如果让浏览器自己判「这题对没对」，那聪明的人可以改一下页面代码，让自己做的题「永远全对」，然后白拿金币、霸占排行榜。所以本项目规定：浏览器只把「你选的答案」发回服务器，对错、得分、金币全部由服务器重新算一遍。客户端说你对了不算数，服务器说对才算对。

这也是「刷币链」为什么被反复堵：总有人想绕过服务端，靠客户端自报成绩骗奖励。每一轮大审计都在查这类漏洞。

什么是「审计」和「AI agent」

审计（audit）就是「请一批独立审查员来找茬」。本项目特别的地方是：审查员不是人，是AI 子代理（agent）——每 60 个或 80 个 AI 被同时派出去，每个负责一个具体领域（比如「查数据库」「查判分」「查文档」），它们自己读代码、自己试运行、自己写报告，最后汇总成一份「体检报告」。

你可以把 60 个 agent 想成 60 个实习审查员，人手一个领域，同时开工，效率极高——人类逐行读几十万行代码要好几天，它们一个多小时就能扫一遍。

什么是「CI」和「测试门禁」

测试门禁 = 每次改动代码后自动跑的一整套检查，全绿才算通过。本项目有一条 9 段的测试链（叫 npm test），涵盖内容校验、接口测试、判分扫描、数据完整性等。CI（持续集成）则是把这些测试放到云端，每次把代码推到 GitHub 就自动跑一遍——现在跑在三个操作系统（Windows/macOS/Linux）上。

什么是 P0 / P1 / P2

给问题分优先级：P0 是必须马上修（安全漏洞、数据丢失）；P1 是重要但可稍缓（功能缺陷、文档错误）；P2 是锦上添花（优化、打磨）。下文会反复用「P0 清单」「P1 项」这种说法。

06第二轮大扫除：crosscheck5

这是「最近发生」的绝对主角。60 个 AI 分六维（文档/项目/半天改动/题目/联网引用/跨平台）同时开工，每维 10 个。结果抓到的东西分四类：

一个会「白屏」的严重 bug

Layout.jsx 离线模式白屏（严重 / critical）

就在当天上午，我改「离线模式提示条」时，在组件里用了变量 user 但忘了声明它。普通模式没事，一旦断网触发离线横幅，页面直接白屏崩溃——而且 CI 还拦不住（前端测试没覆盖这条路径）。三个 AI 不约而同都抓到了它。已修：一行补齐解构。

这件事也给了深刻教训：浏览器层（UI、离线、安全头）此前几乎没有自动化测试，这种前端崩溃放行就是代价。于是后面专门补了一整套浏览器端测试（见下一章）。

三十多处文档与代码对不上

这一轮最密集的发现：文档写的是「旧版本的行为」，代码早就改了。典型的有：

  • README 写「4991 节点」，实际是 5020（多选池扩容后没同步）；
  • 文档说判分用「正则 /安全操作/」，实际是精确匹配（旧的正则正是被修掉的漏洞）；
  • 「13 种题型」实际是 12 种；「8 个限流桶」实际是 9 个；
  • 数据库 schema 里 5 处标着「外键」的表，代码里根本没有外键约束；
  • 运维手册的「回滚流程」会覆盖正在运行的数据库——改成先杀进程、清残留再覆盖。

这类问题一共修了三十多处，涉及 8 份文档。

测试与运维的护城河

修完明面的问题后，重点转向「怎么防止再犯」：

  • 错答负例：判分扫描从只查「正确答案能判对」，升级为 3741 个节点还要「故意答错必须判错」——防止判分变得「怎么答都对」。
  • 幂等键进测试链：防刷币最关键的经济不变量（同一请求重复提交不重复发奖）第一次被自动测试覆盖（17 条断言）。
  • 浏览器 e2e 进 CI：新加了浏览器级端到端测试（安全头、PWA 离线、课程播放器），补上「前端白屏类 bug 无人拦」的漏洞。
  • 前端组件测试：引入 jsdom 给 React 组件写测试，先覆盖最容易出错的「登录/离线/降级」状态机（5 用例）。
  • 移动视口横扫：390px 手机宽度下扫 10 个关键页面，断言没有横向溢出。
  • 若干护栏：e2e 注册被限流时报清晰错误、清理脚本防误删、同步脚本防误清目录、悬停按钮对比度从 2.89 提到 7.5。

07你的七项决策落地

crosscheck5 收官后，你拍板了七个方向，这周全部推进或给到明确结论。

① 模拟考改成「全真模式」

真实低压电工理论机考（按应急管理部新标准）是 100 题 / 120 分钟 / 只有判断和单选 / 80 分及格。原来项目里是 100 题 45 分钟、还带 10 道多选（多选是训练用的）。现在模拟考引擎支持双模式：默认「全真」（100 题 120 分钟，只判断+单选），入口还能切回「训练」（45 分钟含多选）。前端加了模式选择，测试全绿，线上已生效。

② Electron 三平台安装包

项目本身是网页，也可以打包成桌面软件（Windows / macOS / Linux）。难点：桌面软件要自带一个「Node.js 24」环境才能跑后端。现在做到了：

  • electron-builder 配置好，Windows 安装包实测产出（nsis 安装版 + portable 免安装版，各约 105MB），内嵌了 Node 24 和全部后端代码；
  • 打包出来的软件实测冒烟通过；
  • 写好了打包文档和脚本，macOS / Linux 包在对应平台构建即可。

③ 离机备份点（GitHub 私有仓）

本地仓库没有远程备份，硬盘坏了就全没了。现在在 GitHub 建了一个私有仓库 dlg-backup，把含内部审计资料的快照推上去（只排除版权素材），并写好自动备份脚本 backup_remote.cjs——以后跑一下就把最新状态备份到云端。

④ 内网穿透维持并加固

不做云主机、用内网穿透对外——方案是 cloudflared 快速隧道，别人拿到链接就能访问。给它加了「URL 变化记录」（快速隧道每次重连域名都会变，以前没人提醒你，现在会记日志）。

⑤ 固定域名：结论是「还差一个前提」

快速隧道的域名是随机的，你想要固定域名，需要：一个 Cloudflare 账号 + 一个自己的域名（约 ¥50-70/年）。这两样我代替不了你注册，所以这项记录为「待你提供账号/域名后可做」。

⑥ 移动端：在模拟器里测一切

真机暂时没有，那就把浏览器模拟成手机（390px 宽）扫所有关键页面，断言没有横向溢出、没有白屏。已写进 CI，每次推送自动跑。

⑦ 微信小程序：调研结论

个人主体能免费注册小程序，但「教育」类目通常要办学资质。建议：把它归到「工具」类目上线（学习工具而非培训机构），H5/PWA 已经覆盖核心功能，小程序当获客渠道。这项等你决定要不要真去注册。

12视觉升级六项

13八十人审视收官：发现与修复

这一轮 80 个 AI 里，有 57 个成功产出结论。综合六份报告，最值得讲的是这四件事——它们都修了：

① 桌面安装包竟带着真实数据库（最严重）

critical：打包出的 Electron 安装包里藏着真实 app.db

构建桌面安装包时，打包规则把 backend/models/data 整个目录（包括含真实用户密码哈希的 app.db 和几个探针库）一起打进了安装包——105MB 的安装包随手就能解包出用户的数据库。已修：打包规则排除数据库目录、桌面程序改用「每用户独立数据目录」、构建脚本加红线预检（源码树含任何 *.db 直接拒绝构建）、删掉已产出的泄露安装包并重新构建验证。

② 一个「答错反而加心」的经济 bug

high：红心返还逻辑读的是扣心前的数值

游戏里答对一题有 50% 概率返还 1 颗红心。代码在「答错扣心」之前就读取了红心数，返还时用旧值 +1 整体覆盖扣心结果——于是答错 1 题，红心可能不降反升，0 心的人还能被拉回 2 心绕开门禁。已修：返还分支改用扣心后的实时值，并补了回归测试。

③ 每日自动备份两三天一次都没跑

high：03:47 的定时备份被「机器睡着了」静默跳过

服务器每天 03:47 该自动备份数据库，但定时器对「错过的时间」默认不补跑——机器那会儿睡觉，备份就永久漏掉，而且没有任何告警。已修：启动时先检查「今天备份了吗？没有就补一次」，健康检查接口暴露上次备份时间，方便监控。

④ 用户数据第一次真正「离机」

high：离机备份此前不含用户数据库

GitHub 私有备份仓存的是代码快照，但含用户进度/金币/密码哈希的 app.db 因为被 git 忽略，从没离开过这台机器——硬盘坏了数据就没了。已修：设置 DLG_DB_BACKUP_PASS 口令后，备份脚本会把数据库用 AES-256 加密成 db/app.db.enc 随快照推上私有仓（已实测上传）。

其余一批「补课」

  • SM-2 记忆算法补维度：原来判分只有「对/错」两档，导致「难度系数」字段永远不变形同虚设；新增连续失败计数（lapses），判错 8 次标为「顽固卡」（leech），判对一次解除——这是从 Anki 学来的成熟做法。
  • 段位奖励领奖闭环：每周结算后玩家可以「领奖」了（按段位变化发金币，原子防重复领）。
  • 学习分析接口：新增「全库最难题」「我的答题统计」两个数据接口——之前埋点数据存了但没人用，现在能喂给内容校准和成绩报告。
  • 登录会话加固：每用户会话上限 20 条、自动清理过期会话、加索引。
  • 门禁数字自检：新增脚本在 CI 里核对「文档宣称的断言数 == 实测断言数」，数字漂移会直接让构建失败——彻底根治文档数字过时。
